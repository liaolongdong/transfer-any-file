离线文件转换器 vs 在线转换网站：敏感文件该选哪个 Offline file converter vs online conversion site: which one for sensitive files

写于 2026-11-05 · 约 8 分钟 · 作者 Better Written 2026-11-05 · about 8 minutes · by Better

「能不能转」几乎不是这类选择的分歧点——在线站支持的格式确实更多，命令行也确实更好脚本化。真正的分歧只有一条：你的文件要不要先交给别人。这一页把三种做法放在同一张桌子上，只按三件当场能验证的事比：字节有没有离开本机、一批能承受多少、结果能不能在下载前改。反向结论也写清楚——哪几种活就该交给在线站或命令行，这个扩展不该被当成那两样的替身。 Whether a format can be converted at all is rarely where these choices differ — online sites genuinely support more formats, and a command line genuinely scripts better. There is one real fork: does your file have to be handed over first. This page puts the three approaches on one table and compares them on three things you can check on the spot — whether bytes leave the machine, what a batch can hold, and whether a result can be edited before you download it. The reverse conclusions are stated too: some jobs belong to an online site or a CLI, and this extension should not stand in for them.

先说结论：文件属于你自己、属于客户、属于在职或在校材料、属于还没公开给任何人的稿子——选离线那条路，前提是它真的不发请求；要转的是视频音频、一个冷门格式、或者上千个文件的流水线——离线扩展不是那件工具。 The short answer: if the file is yours, a client's, an employer's or a draft nobody has seen yet, take the offline route — provided it really sends nothing. If it is video, audio, an exotic format or a thousand-file pipeline, an offline extension is not the tool for that job.

一、字节有没有离开本机1. Whether the bytes leave your machine

在线转换站不是「顺便」需要上传，它的工作方式就是把文件收过来、在别人的机器上转、再把结果还给你。这意味着隐私政策上那句「文件一小时内自动删除」描述的是一个你无法验证的后续过程，而传输本身已经发生了。离线工具不是更安全一点的在线服务，它把这条路径整段去掉：文件从磁盘直接读进浏览器的页面，转完再从内存交回磁盘。 An online conversion site does not need your file as an incidental detail — receiving it is how it works. The file is collected, converted on someone else's machine, and handed back. So the "your file is deleted within an hour" line in a privacy policy describes a follow-up process you cannot verify, while the transfer itself has already happened. An offline tool is not a slightly safer online service; it removes the path entirely. The file is read from disk into the page, converted, and written back from memory.

「离线」这个词也常被说成一句信念宣言，所以值得给出可查的三条：扩展清单的 permissions 只有 storage，没有 host 权限，浏览器会直接拦下任何离开本机的请求；第一方源码里没有网络调用，仓库用两道守卫分别断言源码层与构建产物层；历史与偏好只写 chrome.storage.local。这三条不依赖任何人守信，而在线站那条主张依赖。 "Offline" is often stated as a belief rather than a checkable claim, so here are three that can be checked: the manifest's permissions list holds only storage and no host permission, which makes the browser block any request leaving the machine; first-party source contains no network calls, asserted by two guards that read the source and the built artefact separately; and history plus preferences go only to chrome.storage.local. None of the three depends on anyone keeping a promise, which is exactly what the online side's claim does depend on.

二、一批能承受多少2. What a batch can hold

真实工作很少是「一个文件」。把一份合同、一张考勤表和三张现场照片一起转成同一种格式，才是一批。在线站的免费档通常在这一步开始收钱：每日配额、单个体积上限、超出后排队或加水印、混合格式要你逐个再传一遍。这个扩展一批最多 200 个文件、单个上限 100 MB（两个上限各自独立：超过 100 MB 的文件被拒收，20 MB 以上只是提示可能慢，仍然照转）；混合格式批次只提供对全部文件都成立的目标，每个文件独立执行自己的路线，一个失败不阻断其余。文件数超过 5 个、或整批合计超过 20 MB，会先弹一次确认——那是防止你误把整个文件夹拖进来，不是配额，而且这个开关可以在偏好设置里关掉。 Real work is rarely one file. A contract, a timesheet and three photos from the field all going to the same format at once is what a batch looks like. Free tiers at online sites start charging at exactly this step: a daily quota, a per-file size cap, a queue or a watermark past it, and a mixed folder you end up uploading one file at a time. Here a batch holds up to 200 files at 100 MB each — two separate caps, where a file over 100 MB is refused while one over 20 MB only gets a may-be-slow warning and still converts. A mixed-format batch only offers targets that work for every file in it, and each file walks its own route so one failure does not stop the rest. Past 5 files, or 20 MB for the batch as a whole, it asks once first — a prompt you can switch off in Preferences, and a guard against dropping a whole folder by mistake rather than a quota.

三、结果能不能在下载前改3. Whether you can fix the result first

格式转换的损往往不在「成不成功」，而在「成功了你没细看」：PDF 出来是整页图像而不是文字层，SVG 被展平成位图，GIF 只留第一帧，文档引用的网络图片取不到字节。在线站一般只给你一张缩略图，你要等到下载完、打开、才发现不对——那时文件已经在别人的机器上过了一遍。这个扩展把源文件和结果左右对照显示，文本类结果可以在下载前就地改再复制出去；并且目标格式选定之后，选择器会先把此刻就能定下来的那三类损失提前列出——PDF 结果是整页图像、矢量源被展平成位图、动图只留一帧——它刻意只做这三类，其余的披露写在结果卡片上。限制不该是下载之后才被发现的东西。 The loss in format conversion is usually not "did it work" but "it worked and you did not look": a PDF comes out as page images with no text layer, an SVG is flattened into a bitmap, a GIF keeps one frame, and images a document references over the network have no bytes to carry. An online site gives you a thumbnail and lets you discover the rest after download — by which time the file has already been through someone else's machine. This workbench shows the source and the result side by side, lets you correct a text result before downloading it, and once you pick a target it flags the three losses that can already be settled — a PDF result is page images, a vector source is flattened, an animated GIF keeps one frame — and stops there on purpose, with the rest disclosed on the result card. A limitation should not be something you find after the download.

什么时候就该选在线转换站 When an online conversion site is the right call

  • 要转的是视频或音频，或任何浏览器解码不动的格式——这个扩展一个都不做，因为它不联网取解码器。 It is video or audio, or any format a browser cannot decode — this extension does none of those, and it will not fetch a decoder over the network to fake one.
  • 只有一个冷门格式的一次性需求，而且文件本身不敏感（一份公开数据集、一张无版权争议的图）。上传一次的成本确实比装一个扩展低。 A single exotic format, once, and the file is genuinely public — a dataset anyone can fetch, a picture with no rights on it. One upload really is cheaper than installing something.
  • 需要 OCR、复杂 PDF 版式还原或云端排版引擎。这类能力要么依赖模型、要么依赖服务器，离线保证和它不能同时成立。 You need OCR, real PDF layout recovery, or a cloud typesetting engine. Those depend on a model or a server, and the offline guarantee cannot stand next to either.
  • 设备受管控、装不了扩展，而且要转的格式不在站点那两张免安装的页面（图片压缩、文件对比）覆盖范围内。 The device is managed and cannot take an extension, and the format is outside the two pages on this site that need no install at all — the image compressor and the file diff.

什么时候该选命令行When to use a command-line tool

  • 上千个文件、定时任务或 CI 流水线里的一步骤：批量就该由脚本与构建系统负责，而不是由一个界面负责。 A thousand files, a scheduled job, or one step inside CI: at that volume the batch belongs to a script and a build system, not to an interface.
  • 需要精确参数与可复现管线——同一份输入在三个月后还要产出同一份字节。 You need exact flags and a reproducible pipeline, where the same input must produce the same bytes in three months.
  • 需要 Pandoc 那种文档格式广度，或 ImageMagick 那种图片格式广度。 You need the breadth of Pandoc for documents or of ImageMagick for images.

反过来说：如果你只是想「把这个文件转成那个格式」，而且不想记参数、不想开终端、想在转完之前先看一眼结果——这正是界面比命令行省事的地方，也是这个扩展存在的理由。 The converse: if the job is "this file into that format", and you would rather not remember flags, open a terminal, or find out only after the fact that the result was wrong — that is exactly where an interface beats a command line, and why this extension exists.

常见问题Questions people actually arrive with

离线转换器怎么证明它不上传我的文件？ How does an offline converter prove it does not upload my file?

三件可以当场查的事：扩展清单里 permissions 只有 storage，没有 host 权限，浏览器会拦下任何离开本机的请求；第一方源码里没有网络调用，仓库用两道守卫分别断言源码层与构建产物层；历史与偏好只写 chrome.storage.local。在线站靠隐私政策承诺删除，而离线这条不需要你相信任何承诺。 Three checks you can run: the manifest's permissions list holds only storage with no host permission, so the browser blocks anything leaving the machine; first-party source has no network calls, asserted by two guards reading the source and the built artefact separately; and history plus preferences go only to chrome.storage.local. An online site asks you to believe a deletion promise; this side asks you to read a manifest.

在线站说文件一小时后删除，这可信吗？ An online site says it deletes files within an hour. Is that credible?

问题是它无法验证。传输已经发生，之后的留存、是否交给子处理方、有没有事故，都不在你的控制范围内——而那正是敏感文件要避免的那一件事。这不是说在线站都在撒谎，而是说这条主张只能靠对方；离线那条主张你可以自己查。 The issue is verification, not honesty. The transfer has already happened; what is retained afterwards, whether a subprocessor sees it, and whether there is an incident are all outside your control — and that is the one thing sensitive files need to avoid. It is not that online sites lie; it is that their claim rests on them, while the offline claim can be checked by you.

设备受管控、装不了扩展，有别的办法吗？ My device is managed and I cannot install an extension. Any other way?

这个站点上有两张完全不需要装东西的页面：图片压缩工具把单张 PNG / JPEG / WebP / BMP / GIF 压到指定体积或最长边，文件对比页把两个文件做行级与词级差异。文件读进页面自己的内存，随页发布的代码里没有任何请求会把文件带出本机，也不从别处取代码。其余格式仍得交给桌面软件，或者——在文件不敏感的前提下——在线站。 Two pages on this site need nothing installed: the image compressor takes one PNG / JPEG / WebP / BMP / GIF down to a target size or longest edge, and the file diff compares two files line by line and word by word. Files are read into the page's own memory, and nothing served with those pages carries your file off the machine or fetches code from elsewhere. For other formats it is a desktop app, or — if the file is not sensitive — an online site.

PDF 转 Word 该用离线还是在线？ For PDF to Word, should I go offline or online?

看你要的是文字还是版式。这个扩展把 PDF 当作文本来源：先提取文字，再写成 Word 或 Markdown——文字可编辑、可选中，但版式、图片位置与表格边框不保留。要贴近原排版的还原是专门的桌面工具或在线服务的活。扫描件还需要 OCR，而这个扩展不内置：内置就得联网取模型，离线保证随之失效。这条路线的取舍单独写在一页上：PDF 转 Word。 It depends on whether you want the words or the layout. The extension treats a PDF as a text source: it extracts text and writes Word or Markdown, so the wording is editable and selectable while layout, image placement and table borders are not. Recovery close to the original layout is a specialist desktop tool or an online service. A scan also needs OCR, which this extension does not bundle — bundling it means fetching a model, and the offline guarantee goes with it. That route's trade-offs have their own page: PDF to Word.

只有 14 种格式，算不算硬伤？ Is fourteen formats a real weakness?

要看你手上实际有几种。这 14 种覆盖日常往来的三类：Markdown、HTML、Word、PDF、TXT、CSV、Excel、JSON，加上 PNG、JPEG、WebP、BMP、GIF、SVG。在线站的几百种里有大量是视频与音频，而那正是浏览器编不动、这个扩展明确不做的部分。按你要转的那几种选工具，比按总数选可靠——总数大的那一边，通常也是要把文件交出去的那一边。 It depends on how many you actually have. The fourteen cover the three groups people trade in daily: Markdown, HTML, Word, PDF, TXT, CSV, Excel, JSON, and PNG, JPEG, WebP, BMP, GIF, SVG. A large part of an online site's hundreds is audio and video, which is exactly what a browser cannot encode and this extension says it does not do. Choosing by the formats you need is more reliable than choosing by the total — and the larger total usually belongs to the side that wants your file.

我已经在用在线站，换过来有什么好处？ I already use an online site. What do I gain by switching?

三件：一，文件不出本机，从此不需要评估任何一家的留存政策；二，断网可用，也没有每日配额与排队；三，结果能在下载前看见、能改。代价也写清楚：格式广度小、没有 OCR、要装一次扩展，而且第一次用 Chrome 的「加载已解压的扩展程序」那条路对非开发者有点陌生。 Three things: the file never leaves the machine, so no retention policy has to be evaluated again; it works with the network off, with no daily quota and no queue; and you can see and correct the result before downloading it. The costs are stated too: less breadth, no OCR, one install, and the unpacked-extension route being a little unfamiliar if you have never loaded one.
