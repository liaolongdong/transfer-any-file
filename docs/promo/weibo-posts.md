## 发帖前必读（微博平台的三条现实）

1. **正文外链会被降权**，且部分用户看不到可点击链接。把仓库地址放**首条评论**，正文里用文字写"评论区见"。
2. **前 2 行决定展开率**。微博在信息流里只露出约 55–60 个汉字，钩子必须在第一句，不要在"大家好"。
3. **9 图上限**，但 3–4 图的完读率通常更高。首图决定点击，用 `preview-edit.png`（左右对照）而不是空界面。

## 版本 A：主贴（技术向长文，约 520 字）

写了一个不联网的 Chrome 扩展，专门治"免费在线转换"的老毛病：你得先把文件传上去。

合同、薪资表、体检报告、没公开的稿子——拖进任何一个"在线转换"网站，那一刻它就已经在别人的服务器上了，然后页面告诉你"24 小时后删除"。那是承诺，不是机制，你没法验证。

所以我把转换全部搬回本地：14 种格式互转，Markdown / Word / PDF / Excel / CSV / JSON / HTML / 图片，批量、混合格式一起丢也行。整个扩展只申请 1 个权限（storage），代码里一个网络请求都没有——不是"我们不看你的数据"，是**没有能把数据送出去的路径**。

几个自己觉得有意思的点：

· 转换对建模成一张有向图，要 A→Z 就在图上 BFS 求最短路径。所以 Markdown→PDF 实际跑的是 Markdown→HTML→PDF，用户只点一次；新增一个转换器约 20 行，所有经过它的路径自动解锁。目前 46+ 条直连路径。
· ZIP 按条目决定压缩：文本走 deflate（能小一个数量级），PNG/PDF/XLSX 这些已经压过的直接 stored，不白烧 CPU。混合批次实测省 47%。
· 中文 CSV 的坑：读 UTF-8 失败自动回退 GBK，写的时候带 BOM，否则 Excel 打开必乱码。
· 没有 OCR，所以图片→文字是置灰并写明原因，不是等你点转换才报错。PDF 输出是图片渲染，文字不可选中——这些限制我全写在 README 里了。

还没上应用商店，目前源码加载（Node 20.12+ / pnpm / build 一下）。仓库地址放评论区，觉得有用给个 Star，这是独立开发者最主要的一条推广路。

## 版本 C：三个开头钩子（同一篇正文可换头）

1. **反常识**：「浏览器本身就是一个文件格式转换器，只是没什么人这么用。PNG/JPEG/WebP 编码、HTML 解析全是内建的，凑一凑就是 14 种格式本地互转。」
2. **具体场景**：「上周要把一份客户合同从 Word 转 PDF。我打开的不是 WPS，是一个'免费在线转换'网站——然后停住了：我为什么要把它传上去？」
3. **数字开场**：「一个扩展，14 种格式、46+ 条转换路径、1 个权限、0 个网络请求。最后一个数字是重点。」

## 与公众号稿的差异（为什么不能直接复制）

| 维度 | 公众号长文                 | 微博                              |
| ---- | -------------------------- | --------------------------------- |
| 长度 | 2000+ 字，允许展开工程细节 | 500 字内，只留一个反差 + 3 个亮点 |
| 链接 | 正文外链转文末参考资料     | 外链进首条评论                    |
| 语气 | 讲清"为什么"               | 讲清"凭什么不一样"                |
| 图   | 概念插画 + 界面截图混排    | 界面截图优先，首图必须能看懂      |
| 话题 | 不需要                     | 3–5 个标签，别堆                  |
